INSTALL
Extract to a NEW folder (do not overlay an old release). Optionally copy your
reports/, scripts/ and settings.json from the old folder, leaving originals intact.
Install dependencies only if needed: python -m pip install -r requirements.txt
Double-click Start.pyw for normal GUI launch without a persistent console.
Windows must associate .pyw with Python's GUI interpreter (pythonw.exe).
Start.cmd is a compatibility shortcut; its console may flash briefly, then closes.
tools/Start-Debug.cmd intentionally keeps the console available for troubleshooting.
The normal launcher redirects Python stdout/stderr to startup.log (replaced on
launch; a temporary log is used if the app folder is not writable). Launch
failures show a message with the log location. This does not start any task.
The running app uses command_relay/assets/relay-icon.ico (transparent, multi-resolution) for its
window and taskbar, with command_relay/assets/relay-icon.png as a fallback. Existing pinned shortcuts
may retain their previous icon; Windows Explorer file associations are unchanged.

SIGNED UPDATES
4.3.0 is the first version intended for signed distribution. Manually extract it
into a fresh directory; unsigned 4.2.0 cannot be updated in place. Keep the ZIP,
.sha256, .manifest.json and .manifest.sig for the installed version together in
an external folder. Never copy the old automation-permissions.json.
Settings > Updates: Check for updates, then Download & Verify for a
newer signed release. Verification alone does not authorize installation.
Enable the separate application-local grant in Safety settings only if desired.
Prepare installation asks for the folder containing the original signed assets
and confirmation to close the GUI. The external updater separately asks for
exact terminal consent before installation and again before optional restart.
The parent directory must be writable, the external Python trusted and able to
import cryptography in isolated mode, and program layout and dependencies unchanged.
Source checkouts, existing caches, unexpected entries and modified files deny
installation. Do not bypass denials, delete recovery markers or copy unsigned
files over a mixed tree. Preserve both signed packages, handoff directory,
transaction evidence and logs; seek reviewed recovery guidance if startup is
blocked. Recovery requires separate terminal consent and can restore the signed
original even after revocation of installation permission. A launched restart
is not proof of GUI readiness. No unattended installation, hostile same-user
or power-loss guarantee. Actual production signed-to-signed GUI updating has not
been demonstrated; use fresh manual extraction if the updater cannot proceed.

QUICK WORKFLOW
Choose your workspace once. Import the AI task, review it, Run commands,
then Copy and paste into the chat. No separate Casual mode or startup mode chooser. The command editor and terminal
occupy the full width. Tools > Show workspace utilities opens the optional bottom
dock with Steps, Scripts and recent History. Find (Ctrl+F) reveals terminal search.
Settings contains theme, language, reduced motion and output display options.
Protected Copy and compact text exports are prepared in a worker; wait for Copied before pasting.

INPUT
Use TXT, PS1, pasted commands or command-relay/task-v1 JSON. The single stage
syntax is @step Title. Stage numbers are generated automatically. Retired stage
directives are rejected before execution. Old script files are not converted.
Old reports are preserved as text; obsolete footers are not recognized, so
history may show Unknown. Use View full or Ctrl+click Copy for raw evidence.
Do not rely on structured metrics or compact extracts for old reports.
Task metadata is advisory; the workspace never changes automatically on import.
Import does not execute; Run or Ctrl+Enter starts the reviewed editor contents.
No mandatory AI API, credentials, uploads, telemetry or execution-policy override.
Optional GitHub tools use authenticated GitHub CLI and can make explicit remote writes.
Review the intended repository, PR, CI and commit identity before authorizing a merge.
Ordinary manual Run and known successful repeats need no extra confirmation.
High-risk findings require exact one-use approval; failed or uncertain repeats
require separate confirmation. The absence of a heuristic match is not safety.

COPY
Click Copy: AI result JSON (command-relay/result-v1), compact JSON encoding.
Whitespace between JSON fields is minimized; detected secrets are masked in exported data.
Shift+click: protected text. Ctrl+click: RAW full report without masking (Ctrl wins).
Smart JSON folds recognized verbose success lines where applicable; Detailed JSON
uses the prior bounded view. Assertions and comparison use the complete source
within existing scan limits. Reports up to 48,000 Unicode characters otherwise
fit in full before privacy masking; larger reports use a bounded extract. The budget is
for the output field, not the whole JSON packet. Git hash/ref lines are selected
along with structured results and the beginning/end. For oversized extracts,
whole lines may still be omitted to fit; no guarantee that every hash survives.
The result-v1 schema is unchanged with additive fields: omitted_lines,
filter_omitted_lines, budget_omitted_lines (blank lines count too). A full
payload has view=full and zero omissions. budget_truncated means extra budget
reduction was needed after filtering. History compact comparison uses the same
bounded view. Ctrl+click always provides the original unfiltered report.
Compact extracts may omit important context; process exit is not a test verdict.
Inspect data before sharing. Full report is streamed to disk and archived.

AI INTELLIGENCE
Optional task-v1 assertions: exit_code and up to 16 scalar equality checks
(metrics, key/equals/occurrence all or last). Evaluated against the complete
report when copying AI JSON, before any text omissions. No declarations means
NOT_REQUESTED; missing evidence, cancelled/partial runs and edited imported
tasks are INCONCLUSIVE. A PASS means the declared checks matched the text,
not independent verification. Process status remains separate.
New runs record a lightweight start-of-run project snapshot: fixed root file
markers, marker-based technology hints and Git HEAD when readable from a normal .git directory (detached or
loose ref). No Git subprocess, recursive scan, source text or remote URL.
Packed refs, worktree gitfiles and other layouts may report unknown HEAD.
Smart Evidence returns heuristic counts and bounded examples for compact logs.
Structured zero failure/error counts are not errors. Explicit path-shaped
artifact metrics are hints only; no files are opened or verified automatically.
Automatic evidence/assertion scan limit: 8,000,000 characters; lines over
16,384 characters are skipped with a visible limitation. Original logs stay
unchanged. Additional JSON fields are outside the 48,000-character output cap.
Tools > Project > Project context is optional for a fresh lightweight snapshot.

SESSION HANDOFF (NEW CHAT)
Run history is saved automatically in the existing reports/ folder. New runs
record task title, purpose and expected outcome (up to 300 characters each,
only when the imported script is unchanged). No separate session database.
To continue in a new AI chat: select the same WORKSPACE, choose Tools > Copy
session context, wait for Copied, then paste into the new chat with the guide.
A command-relay/session-v1 packet contains up to 12 recent matching archived
runs, their reported exit/cancellation status, available Git HEAD, declared
intent, report identity, assertion checks and evidence counts when scanned.
The export runs in a worker, with no startup scanning or extra network access.
Normal Copy still returns only the selected run. Session summaries are not
sent automatically. No raw log excerpts or source files are included; task
metadata and metric values may still be sensitive, so review before sharing.
Limits: 10,000 directory entries, 250 newest candidate archive headers,
512,000 bytes per full report scan, 4,000,000 body bytes total, and 24,000
characters for the compact session JSON. Older rows may be omitted; limits are
reported. Larger reports use header/footer only and NOT_EVALUATED assertions.
Matching uses normalized absolute workspace paths, not repository identity;
relative historical paths, aliases and moved workspaces may not match.
This is local run history, not conversation memory, verified project progress,
or an automatically inferred next task. Old reports lack newer task intent.

AUTOMATIC COMPARISON AND ARTIFACTS (3.6)
Normal Copy includes comparison and artifacts. No additional action is needed.
Repeat the identical imported task in the same workspace to compare against
the nearest earlier matching archive. Matching requires task ID, editor hash,
prepared script hash, unchanged import and identical assertion criteria.
Reports from other workspaces, future reports and edited tasks are excluded.
The earlier matching run must be complete, not cancelled and not inconclusive.
Limits: 10,000 directory entries, 100 older headers (32 KiB each), one baseline
body up to 512,000 bytes. If unavailable, comparison explains why. The JSON
reports process exit, assertion transitions, last declared metric values and
heuristic warning/error/test-line counts; Git HEAD changes are shown if known.
These are observations, not proof of regression, improvement or identical
environments. All AI Copy operations run in a background thread. No startup
scan, network requests or new dependencies. Raw report export is unchanged and NOT masked.

Artifacts are reported path hints from explicit KEY=value or single-line JSON
fields: ARTIFACT, ARTIFACT_PATH, OUTPUT_FILE, OUTPUT_PATH, REPORT_FILE, LOG_FILE,
RESULT_DIR, BUILD_FILE, BUILD_DIR, BINARY_FILE, EVIDENCE_FILE, MANIFEST_FILE.
Up to 12 distinct key/path pairs, 512 characters per path, with line numbers.
Relay never opens or checks these paths or attaches their files automatically.
The task must report creation/existence/hash checks separately if needed.
The ordinary output field keeps the existing full/compact selection budget and accounting before masking.
To smoke-test comparison, run examples/example-ai-task.json twice in the same workspace,
then Copy. The second result should show comparison.status=compared and COUNT
delta=0, with both assertion statuses PASS. First run may have no baseline.

TRUST AND PRIVACY (3.7)
Task Inspector scans editor text after a brief debounce, then checks the
prepared script at Run. Ordinary tasks have no new confirmation. Detected
network, file/repository and install patterns show a small advisory label.
High-risk patterns (e.g. recursive deletion, disk operations, force push,
security settings, dynamic execution) require a separate confirmation; No is
selected by default. The inspection is heuristic, not a PowerShell parser,
security boundary or sandbox. False positives and missed effects are possible.
New reports record the inspection summary (line numbers refer to the prepared
script); no raw matched command snippets are exported by the inspector.

Default AI Copy, Shift+click text, session context and tool JSON previews/exports
apply best-effort local masking of recognizable credential assignments,
credential fields, common token shapes, authorization/cookie headers, URL
credentials and private-key blocks. The app also masks bounded repeated values
where detected, including assertion/evidence/comparison fields. Relay does not
send any data to a service. Masking is not complete anonymization; review every export.
User names, local paths, arbitrary secrets, split/encoded values and other
sensitive data may remain. Some ordinary strings can be masked by mistake.
The privacy object reports status (redacted/no_matches), replacements (not a
count of distinct secrets), source_scan_limited and alias_limit_reached. Full
source alias discovery is capped at 8 million characters; all exported text
fields are scanned. Repeated-value matching is bounded. Assertions/comparisons
are computed on unmasked evidence before export. Hashes and line counts refer
to the original report; view=full means no compact selection omissions, not
necessarily byte-identical output. Masking can change output length and lines.
If protection fails, the protected export fails rather than falling back to raw.
Ctrl+click Copy, Ctrl+Shift+C, View full, Open latest, Evidence ZIP, local logs,
and manual selection from the editor/terminal are RAW and may contain secrets.
Do not share raw data without reviewing it. No automatic upload or deletion.

WINDOWS SMOKE TEST
Run examples/example-ai-task.json normally; expect PASS and privacy.status=no_matches.
Then optionally run examples/example-privacy-task.json and use normal Copy. Expect PASS,
privacy.status=redacted, [REDACTED] in both fictional password occurrences and
one reported artifact hint (not verified existence or creation). No real
credentials, file writes by the task, network, or risky commands are needed.

FAST RESULTS (3.8)
After a run is archived, Relay may prepare the protected AI JSON locally in a
background worker (one speculative worker; reports up to 1,000,000 bytes).
Normal Copy reuses this result if the report, archive directory and selected
baseline still have matching file metadata. This is best-effort freshness,
not a cryptographic integrity check. An early click waits for that worker,
then uses the ordinary protected export if needed. Larger reports, older
reports and other copy modes are prepared on demand. No clipboard change
occurs without an explicit copy action. No additional files, dependencies,
network access, schema changes or automatic execution are introduced.
If a run cannot be archived, Copy must not silently return an older run.
Wait for Copied before pasting. The optional Browser Bridge is described below.

4.0 STABILITY UPDATE
The regular Import > Run > Copy workflow and task-v1/result-v1 schemas stay
unchanged. Invalid JSON-looking objects are rejected during import instead
of being passed to PowerShell. Report identity fields are read only from the
report header, not from similar-looking lines printed by the task. This is
not authentication of report contents.
The visible terminal is additionally bounded to about 512,000 Python text
characters (with a smaller target after trimming) and 6,000 Qt blocks.
Long outputs may lose earlier display text or reset the visible selection;
original archived reports and export evidence are unaffected. Restoration
reads at most 2 MB. Use View full or a reviewed report export for older text.
History loads metadata in a background worker; search and filters reuse the
snapshot, with a short debounce. Refresh explicitly reloads it. The window
lists up to 3,000 recent reports from at most 50,000 directory entries and
shows a notice when limited. Older files are not deleted; access them in
Tools > Reports > Folder. If the directory enumeration limit is reached,
not all recent reports may have been seen. A new run waits until an explicitly
requested Copy finishes to avoid confusing report ownership. The app does
not copy automatically. No new dependencies, network actions or mandatory
controls. The optional Browser Bridge is described below.

4.4 CANDIDATE FEATURES AND LIMITS
Queue > Task batches reviews command-relay/batch-v1 dependencies and workspaces.
Sequential is default; parallelism is opt-in for independent, distinct,
non-overlapping roots. Each task retains its own report and declared assertions.
Failed dependencies block downstream tasks; Stop is not rollback. Windows Job
Objects support process ownership and cancellation, not isolation.

Skills imports declarative command-relay/skill-v1 revisions into
%LOCALAPPDATA%/CommandRelay/User/skills (home AppData fallback). Copy instructions
or load a template explicitly; neither grants authority nor starts execution.
Tools also offers reviewed plan-v1 fixed read-only metadata operations and runtime
diagnostics; no arbitrary shell, file-content reading or writes in plan-v1.

AI Chat is optional, lazy and off-record. Enter a provider HTTPS address (loopback
HTTP for local tests). Same-origin JSON downloads are validated and must be
explicitly imported. No task executes on download. For return, use protected
clipboard Copy or prepare a masked report draft in a supported empty HTML textarea.
Review then Insert draft; the page receives text at insertion. Send manually.
Unsupported providers use an external browser and clipboard. No persistent
provider profile, automatic Send, delivery guarantee or mandatory API key.

Settings > Language offers English/Russian and 15 labelled preview translations.
Arabic chrome is RTL; raw paths, commands and report editors remain LTR.
Preview startup notices include the original English text. OS controls, external
provider text and raw technical output may not be translated. Independent
linguistic/legal review and actual native DPI acceptance are outstanding.
